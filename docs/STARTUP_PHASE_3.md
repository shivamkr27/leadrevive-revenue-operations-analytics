# Phase 3 local startup and verification

Working directory: `D:\project 1 -nontech`. Docker Desktop must be running. All services bind to loopback: application 8000, n8n 5678, Mailpit 8025/1025, PostgreSQL 5433. No paid account, external SMTP credential or Google/OpenAI credential is needed.

## Start the verified system

From the project root in PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start_phase3.ps1
```

The script preserves existing local secrets, starts Docker providers, verifies/migrates PostgreSQL, builds the app, and configures n8n only if its four project workflows are absent. Existing configured workflows—including intentionally unpublished ones—are preserved on later startups. It does not reset records or replay seed data over PostgreSQL edits.

Open:

- Application: http://127.0.0.1:8000
- n8n: http://127.0.0.1:5678
- Mailpit: http://127.0.0.1:8025
- API documentation: http://127.0.0.1:8000/docs

The local n8n owner email/password are in the ignored `.env` file generated by `configure_phase3.py`. Read them locally when signing in; do not paste them into chat or commit them. The shared header credential is encrypted in n8n's credential store; workflow exports contain only its ID/name. Configuration scripts never print secret values.

Stop or restart without deleting data:

```powershell
docker compose stop
docker compose start
```

Do not use volume deletion to resolve startup issues; it removes persisted databases/messages/workflows. SQLite originals and timestamped backups are retained under data/processed and data/backups, both ignored by Git.

## Use the workflows

1. Open **Automations**. Verify n8n and Mailpit are reachable.
2. **Run recovery workflow** invokes the real n8n W2 webhook, reserves eligible overdue work, groups owner digests and sends them to Mailpit. Completed/closed/unassigned/suppressed/cooldown items are excluded.
3. Open a lead → **Prepare Mailpit preview** → Automations → select its pending-approval outbox item. Review body, intended contact and actual sink mailbox.
4. Check the explicit sink-only approval box → **Approve Mailpit preview** → **Send approved preview to Mailpit**. Inspect its approval and delivery ledger, then open Mailpit.
5. Review failures/retry eligibility and retry or cancel a pending test message with a note. Original records and evidence are retained.

Hourly recovery and five-minute outbox schedules run only while n8n is running and the relevant workflows are published. Existing exported workflows are in automation/n8n/workflows; downloadable copies are available from the Automations screen. An unconfigured/down provider is not reported as healthy.

## Operational boundaries

- DRY_RUN means local preview/Mailpit capture. The SMTP transport only accepts local Mailpit hostnames/port; arbitrary providers and `mode=live` are rejected.
- SMTP acceptance is not external delivery. An unresolved acknowledgement is not automatically resent; it requires sink reconciliation/operator review.
- A contact after its overdue next-action time prevents another reminder for that completed action; update its next action to maintain the follow-up schedule/KPI.
- Keep one app worker for the local interface. PostgreSQL locks and reservations were tested for concurrent scans; this is not a production deployment/security claim.
- Power BI, management-report generation and the controlled before/after analytics experiment remain later phases.
